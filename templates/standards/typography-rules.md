# 排版与 Markdown 解析规范

## 一、标题映射原则
- **禁止多 H1**：单篇文档全局只能有一个 H1 主体（这是 Outline 的底层解析特性，它将你的第一个 `#` 视为页面标题）。
- **小节规划**：正文中的每一个独立逻辑部分，必须从 `##` (H2) 开始往下递进。标题需附带清晰的中文前缀序号（如“二、系统流程”）。

## 二、高亮警示块 (Callouts)
- 合理使用块引用区分层级内容，Outline 兼容 Github Flavoured Markdown 的 Callout：
  - `> [!INFO]` 或 `:::info` 用于背景补充说明。
  - `> [!WARNING]` 用于阻断性或关键性流程提醒。

## 三、强制留白策略
- Outline 解析器通常会吞并多余的换行符（回车）。
- 如果你在前后有配图的段落间，想要拉开视觉排版空间，必须使用原生的 `<br>` 标签插入换行，以此保持文档透气性。

## 四、代码块格式化
- 不要使用纯文本存放 JSON / 代码！务必在反引号后加上对应的语言名称（如 ```json， ```python），确保代码高亮能够正确命中。
