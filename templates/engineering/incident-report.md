# 故障复盘报告 (Incident Postmortem)

## 一、故障概要
- **摘要描述**：高度提炼。如：由于 XXX 导致 YYY 服务在 XX:XX 分钟内崩溃，引发 ZZ 个客诉。
- **严重等级**：P0 / P1 / P2

## 二、时间线还原 (Timeline)
- `10:00` 报警群内飞书告警报错率飙升。
- `10:05` 值班人 XXX 响应，拉起线上会议。
- `10:30` 确认是某个 commit 导致的死锁。
- `10:35` 回滚服务，线上指标恢复正常。

## 三、根因分析 (Root Cause)
- **直接触发点**：某个特定条件的并发进入。
- **深层原因 (5 Whys)**：为什么测试环境没测出来？为什么监控过了 5 分钟才报警？

## 四、改进项跟进 (Action Items)
> 每一个改进项必须指定对应的 Owner 且有明确的 Deadline。
- [ ] 增加针对此 Case 的高并发自动化测试用例（@XXX，Deadline: x月y日）
- [ ] 完善报警阈值过滤（@XXX，Deadline: x月y日）
